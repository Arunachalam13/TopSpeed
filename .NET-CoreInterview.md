# ASP.NET Core Backend Developer Interview Notes

## What is .NET Core?
.NET Core is a free, open-source, cross-platform framework for building modern applications, including web, cloud, mobile, and IoT. It is modular, lightweight, and designed to work on Windows, Linux, and macOS.

---

## Advantages of .NET Core over .NET Framework

| .NET Core                               | .NET Framework                         |
|----------------------------------------|---------------------------------------|
| Cross-platform (Windows, Linux, macOS) | Windows-only                          |
| Open-source and community-driven       | Microsoft-managed                     |
| Modular with NuGet packages            | Monolithic with large base libraries |
| High performance and scalability       | Lower performance in some workloads  |
| Supports microservices and containers | Limited container support            |
| Side-by-side versioning               | Single version on machine           |
| CLI tools support                     | Mainly Visual Studio-based tooling  |

---

## Default Project Structure in ASP.NET Core
- **Program.cs** → Entry point, builds and runs the host
- **Startup.cs** → Configures services and middleware
- **appsettings.json** → Configuration file
- **Controllers/** → Controller classes
- **Models/** → Model classes
- **Views/** → Razor views (MVC projects)
- **wwwroot/** → Static files (CSS, JS, images)
- **Properties/** → Project settings

When you create a new ASP.NET Core project, it follows a well-organized folder structure:

| Folder/File             | Purpose                                                                                 |
|-------------------------|-----------------------------------------------------------------------------------------|
| **wwwroot**            | The web root. Static files like CSS, JavaScript, images are stored here.                |
| **Controllers**        | Contains controller classes that handle HTTP requests and responses (MVC or API).        |
| **Models**            | Contains model classes that define the data structure and business logic.               |
| **Views**             | (Only for MVC projects) Contains Razor (.cshtml) files for the UI, organized by controller. |
| **Pages**            | (Only for Razor Pages projects) Contains Razor Pages (.cshtml) and related code-behind. |
| **Program.cs**        | Entry point of the application. Sets up the WebApplication, services, and middleware.     |
| **Startup.cs** (older) | Configures services and the HTTP request pipeline. In .NET 6+, merged into `Program.cs`. |
| **appsettings.json**  | Configuration file for settings like connection strings, logging, etc.                   |
| **Properties/launchSettings.json** | Settings for how the app should be launched (IIS, Kestrel profiles, etc.).   |
| **Dependencies**      | Shows project dependencies (NuGet packages, SDKs).                                       |

## Dependency Injection in ASP.NET Core
Dependency Injection (DI) is a design pattern where dependencies are provided from the outside rather than created inside a class. ASP.NET Core has built-in DI, configured in `Program.cs` or `Startup.cs` using `IServiceCollection`.

**Example:**
```csharp
services.AddScoped<IProductService, ProductService>();
```
In controller:
```csharp
public class ProductsController : Controller
{
    private readonly IProductService _service;
    public ProductsController(IProductService service)
    {
        _service = service;
    }
}
```

## What is Middleware?
Middleware is software that handles requests and responses in the ASP.NET Core pipeline. Each middleware can:
- Process the request
- Pass it to the next middleware (`next`)
- Short-circuit the pipeline

**Example:**
```csharp
app.Use(async (context, next) => {
    await context.Response.WriteAsync("Before next\n");
    await next.Invoke();
    await context.Response.WriteAsync("After next\n");
});
```

## What is Kestrel / In-process vs Out-of-process Hosting?
- **Kestrel:** Lightweight, cross-platform web server for ASP.NET Core.
- **In-process hosting:** ASP.NET Core runs inside IIS process (better performance).
- **Out-of-process hosting:** IIS acts as a reverse proxy to the Kestrel server.

---

## Difference between Kestrel and IIS
| Kestrel                      | IIS (with ASP.NET Core)        |
|-----------------------------|--------------------------------|
| Cross-platform web server   | Windows web server + manager  |
| Lightweight and fast        | Mature, feature-rich, Windows-only |
| Needs reverse proxy in production (IIS, Nginx) | Provides reverse proxy and process management |

## Run, Use, and Map Methods
- `Run` → terminal middleware, ends pipeline
- `Use` → adds middleware, calls next()
- `Map` → branch pipeline based on request path
```csharp
app.Use(async (ctx, next) => { await next(); });
app.Map("/map", app => { app.Run(async ctx => await ctx.Response.WriteAsync("Mapped")); });
app.Run(async ctx => await ctx.Response.WriteAsync("Final Run"));
```

## Routing in ASP.NET Core
- Matches incoming requests to endpoints.
- Example:
```csharp
app.UseRouting();
app.UseEndpoints(endpoints => {
    endpoints.MapControllerRoute(
        name: "default",
        pattern: "{controller=Home}/{action=Index}/{id?}");
});
```

## ASP.NET Core MVC Request Processing Pipeline
1. Middleware pipeline → `UseRouting`
2. Routing → find controller/action
3. Model binding → bind inputs to action parameters
4. Model validation
5. Action filters
6. Action execution
7. Result execution (view or JSON)
8. Response sent

## Custom Middleware
```csharp
public class MyMiddleware
{
    private readonly RequestDelegate _next;
    public MyMiddleware(RequestDelegate next) => _next = next;
    public async Task Invoke(HttpContext context)
    {
        await context.Response.WriteAsync("Before Middleware\n");
        await _next(context);
        await context.Response.WriteAsync("After Middleware\n");
    }
}
```
Register:
```csharp
app.UseMiddleware<MyMiddleware>();
```

## Session and State Management
- TempData → uses cookies/session, lasts across requests
- ViewData → dictionary, single request
- ViewBag → dynamic, single request
- Cookies → store small data on client

**Examples:**
```csharp
TempData["msg"] = "Saved!";
ViewData["msg"] = "Hello";
ViewBag.Msg = "Hi";
Response.Cookies.Append("key", "value");
```
